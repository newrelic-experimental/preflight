'@newrelic/preflight': patch
---

A session in the "Sessions today" tile now leaves "Ready for review" when its pull request is merged from a separate clone of the same GitHub repo, not only from a worktree of the clone that opened it. Preflight now saves the pull request's `owner/repo` alongside its number, read from the same URL in the `gh pr create` or GitHub MCP output, and matches the merge on `owner/repo#N`. A `gh pr merge` gets its repo from `-R`/`--repo` or a `GH_REPO=` prefix, which used to stop it matching at all, or else from the repo's only remote. Without `-R`, a merge in a repo with more than one remote, such as a fork clone with `origin` and `upstream`, still matches only within its own clone, unless `gh repo set-default` has saved a default repo. A merge by a session that started before midnight now clears a pull request opened today, and a session that started before midnight and opened a pull request today now reads "Ready for review". Sessions saved before this release have no recorded repo, so a merge from another clone still leaves their pull requests open.
