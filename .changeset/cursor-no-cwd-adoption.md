**A Preflight server no longer takes over another coding assistant's session when the hook collectors are current.** A server started by Cursor, Kiro, or any other assistant could adopt the session of a Claude Code session running in the same directory or under the same parent process, and record its own cost on that session. The hook collector now records which assistant wrote each session breadcrumb. Next to a current collector, a server adopts only the breadcrumbs its own assistant's hooks wrote. Next to an older collector, a server also adopts that collector's untagged breadcrumbs, because the older collector writes them for every assistant. So a Kiro server next to an un-upgraded Claude Code collector can still adopt a Claude Code session. This gap exists on main too, and this change does not close it. Servers for assistants whose hooks write no breadcrumb, such as Cursor, Windsurf, and Zed, and servers whose assistant Preflight cannot identify, no longer wait for one. Kiro, Codex, Copilot, and other assistants whose hooks were installed before their setup docs named the assistant still resolve from breadcrumbs that name no assistant. A plugin that is behind the server keeps working through its ppid breadcrumb, which the older collector keeps writing. The cwd fallback for an older collector is restored by the follow-up fix, which ships with this change.
