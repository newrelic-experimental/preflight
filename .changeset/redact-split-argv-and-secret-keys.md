**Recorded content now hides a secret that is split across an argv array or named only by its JSON key.** With `NEW_RELIC_AI_MCP_RECORD_CONTENT=true`, `inputContent` and `outputContent` redacted each string on its own, so `{"args":["curl","-u","me:pw"]}`, `{"args":["--password","pw"]}`, `{"password":"pw"}` and `{"headers":{"Authorization":"Basic …"}}` were stored as they came. An array of strings and numbers is now also read as the command it spells, and a word that the command rules hide is stored as `[REDACTED]`, so the first two are stored as `["curl","-u","[REDACTED]"]` and `["--password","[REDACTED]"]`. A string or number under a key that names a secret is stored as `[REDACTED]`, and so is each string or number of an array under that key, as in `{"password":["pw"]}`. Such a key ends in a name the `NAME=` rule or a secret flag already takes, such as `password`, `API_TOKEN`, `apiKey`, `X-Api-Key` and `aws_secret_access_key`, or in `Authorization`. Keys that only start with one, such as `passwordPolicy`, `password_file`, `max_tokens` and `authorization_url`, keep their values.
