**Breaking: Preflight no longer sends the `SecurityAlert` event. Each security alert is an `AiAuditEvent` only.** Every triggered alert was sent twice, as an `AiAuditEvent` and as a `SecurityAlert` event, and no shipped dashboard or alert read the second one. Preflight now sends the `AiAuditEvent` alone, with `audit.security_alert = true`, `audit.severity`, and `audit.alert_type` set on it. Any saved query, dashboard, or alert condition on `FROM SecurityAlert` stops getting new rows. Replace `FROM SecurityAlert WHERE severity = 'critical' FACET alert_type` with `FROM AiAuditEvent WHERE audit.security_alert = true AND audit.severity = 'critical' FACET audit.alert_type`. The `SecurityAlert` `description` field has no counterpart on `AiAuditEvent`. Its `detail` field holds the tool and the file path or command instead. Rows sent by earlier versions keep `SecurityAlert`. The local audit trail and its alert classification are unchanged. A tier that lists `SecurityAlert` alongside other event types loads, logs a warning, and drops the name, so its alerts then need `AiAuditEvent` routed to it explicitly. A tier that lists only `SecurityAlert` fails at startup until you edit it to list `AiAuditEvent`, which is `personal-only`.
