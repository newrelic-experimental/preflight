**Secrets passed as command arguments are now redacted before they reach New Relic, local storage or the dashboard.** This covers the value after `--token`, `--password`, `--passwd`, `--secret`, `--api-key`, `--access-key`, `--secret-key` or `--private-key`, in single-dash, underscore and `=` forms, and after the same names with more words joined in front by `-` or `_`, such as `--access-token`, `--client-secret` or `--db-password`. It also covers each `-p<password>` among the arguments of a `mysql`, `mysqldump`, `mysqladmin` or `mariadb` command, except a docker-style `-p3306:3306` port mapping, an `X-Api-Key`, `Api-Key`, `X-Auth-Token` or `X-Access-Token` header passed with `-H` or `--header`, and a 40-character `aws_secret_access_key` value. The value is read the way bash reads one word: quoted parts, backslash escapes such as `\ `, `$'…'` strings and `\` line continuations stay in it, and an unquoted space, tab, line break, `;`, `|`, `&`, `(`, `)`, `<`, `>` or backtick ends it, so the command after it stays in the audit trail. Inside a double-quoted string, such as a JSON value, `\"` is read as a quote and `\n`, `\r` and `\t` as whitespace. A value inside a quoted string, such as `echo "API_KEY=x" >> .env`, ends at the closing quote at the latest, and the quote stays. A quote that never closes is read as a plain character, so the value ends at the next space or operator. If a quoted part holds more than 4,096 characters, the value ends at its first quote or backslash, and the rest is not redacted. A `=` or `:` followed by spaces takes the next word on the same line, so `--password= db` hides `db`. The flag or header name is redacted together with its value, the same way `API_KEY=value` already was. That `API_KEY=value` rule now also matches a longer name that ends in one of its names, such as `PGPASSWORD=`. Flags that name a file or stdin, such as `--token-file` and `--password-stdin`, are left as they are. An odd apostrophe in prose or a heredoc body reads as an open quote, so after one a single-quoted or `$'…'` value is redacted only when each quoted part holds no space, line break, backslash, quote, `$` or shell operator, and otherwise the quoted part stays raw. Also not covered: a quote nested unescaped inside `bash -c "…"`, a CRLF line continuation inside a quoted string, JSON-escaped text such as `\\ ` outside a JSON string, `--passphrase` followed by a space, `--auth` in any form, and an `Authorization:` header value without `Bearer`. An `API_KEY=`-style value still hides at least what the earlier rule hid, every character up to the next space or shell operator, but keeps each quote, backslash and `$` past the end of the shell word, so the command after it is read the same. The audit classifier still misses a destructive command after a `# Don't` comment or after an escaped `it\'s`, as on main.
