**Older and newer Preflight versions keep finding the right session as you upgrade.** The hook collector still writes session breadcrumbs where servers from before this release look, so a server pinned to an older release keeps resolving. A current server reads those copies only when no assistant-tagged breadcrumb names the same session, so it does not adopt another assistant's session from a collector that has been upgraded. A collector that has not been upgraded writes only the old layout and names no assistant, so a current server of another assistant can still adopt a session it wrote after the server started. A server restarted mid-session resolves from an older collector's breadcrumb on the session's next tool call. A server prefers its own assistant's breadcrumbs over unattributed and older ones. An assistant name spelled differently, such as `MCP_CLIENT=Kiro` or `claude_code`, is now recognized by both the hook and the MCP server, and events are tagged with the registered name (`kiro`). A name Preflight doesn't know, such as an inherited `MCP_CLIENT=vscode`, no longer hides Claude Code. When nothing else identifies the assistant, or a hook names `generic-mcp`, that hook files its breadcrumb as unattributed, and an unknown name prints a warning.
